A staging Kustomize overlay failed to set intended API limits because its strategic merge patch referenced api-old after the base renamed the container to api-main. Render inspection found an unintended extra container without an image, which would fail admission, and the suspicious output had not been applied. Correcting the patch produced exactly the main container and sidecar, left sidecar resources unchanged, and passed server-side dry run. The reviewed rollout used the intended limits, and render tests now assert container names and count.
