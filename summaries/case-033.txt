A new rehearsal test runner could not call the pricing API because it lacked a mesh sidecar and sent plaintext to a destination enforcing strict mutual TLS. Sidecar inspection and destination logs confirmed the mismatch, and the runner's approved design required mesh participation. Reviewed injection configuration created a replacement runner with the expected identity, already permitted by existing authorization policy. Requests succeeded while an unmeshed negative test remained rejected, preserving mutual TLS enforcement.
