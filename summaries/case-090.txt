A streaming demo continued using an unready pod because its TCP connection predated the readiness change, while new clients correctly selected other ready replicas. Investigation clarified that readiness removes endpoint eligibility for new traffic but does not migrate existing streams. The application's supported drain protocol sent a final message, waited for acknowledged completion, and closed the connection for bounded reconnection. Rehearsal tests verified reconnection to a ready replica with continuous message sequencing, and the runbook and acceptance tests now cover existing connections explicitly.
