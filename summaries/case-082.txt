A rehearsal canary passed readiness but failed response-contract tests because its new serialization configuration returned a numeric item count as a string. Identical synthetic inputs reproduced the difference against the previous build, and the application owner confirmed an incompatible encoder option rather than a cluster or routing defect. Promotion stayed blocked, and the approved rollback returned traffic to the verified previous build with passing contract checks. The contract test became a release gate, while the faulty build remained rejected pending a tested application fix.
