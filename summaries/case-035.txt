New sandbox pods on one node lost Service connectivity after a CNI rollout because that node's CNI agent could not parse an obsolete override option. Comparison with healthy nodes isolated the unready agent and its configuration error despite the node remaining Ready. The network owner cordoned the node, corrected only the stale option through the managed workflow, and used the supported agent recovery procedure. Disposable-pod DNS and Service tests plus dataplane checks passed before scheduling resumed, and new pods connected normally.
