A hardened preview pod failed at startup because it tried to create a disposable cache under /var/cache/demo on its newly read-only root filesystem. Investigation identified that path as the only required startup write and confirmed it did not need persistence. A reviewed bounded emptyDir mount with non-root-compatible ownership supplied access only at the cache path. Startup and synthetic cache eviction tests passed within budget, the rest of the root filesystem remained read-only, and documentation now lists writable paths.
